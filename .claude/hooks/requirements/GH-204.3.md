### GH-204.3
- text: The suite reads its own text through `$SUITE_TEXT`, which `suite_text`
  writes from every file of the suite in source order, and through
  `suite_range`, which FAILs when the range it is given matched nothing; a check
  that needs to know which file a line is in reads the files `$SUITE_FILES`
  lists, in the same order. No code names `check-hooks.sh` under `$SUITE_DIR` or
  `$HOOKS` except the line that sets `$SUITE_FILES` and the one that runs the
  suite.
- from: #204
- kind: defect-permitting
- status: active
- direction: static: it reads the suite's own code and drives one of its helpers
- note: A read of `check-hooks.sh` alone stops seeing a function the moment it
  moves into the library, and `sed -n '/a/,/b/p'` over a file where `a` is gone
  prints nothing and exits 0. Then a pin on an absence passes, and a derivation
  over the empty text agrees with an empty expectation. Both are the permitting
  direction, and neither says so. What is not asked, named: a relative spelling,
  a bare `check-hooks.sh` read from the suite's own working directory -- the
  #107 rule asks that of the three text-check helpers, and nothing asks it of a
  bare `grep`; and `$0`, which every awk program here spells as its record, so
  a shell `"$0"` cannot be told from one by its text.
