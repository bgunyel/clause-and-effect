### GH-204.6
- text: The driver sources every file under `checks/` other than the library
  through one routine, `source_checks`, into its own shell, in the order of one
  list it writes. For each file the routine records a start marker, clears
  `REQ`, sources the file, and clears `REQ` again, so a `req` a file ended
  inside reaches neither the next file nor anything after the last. It fails
  the run on a file the list names and the directory does not hold; on a file
  the directory holds that no list names, the library aside; on a file whose
  last line is not `sourced_to_end`, the call that writes its end marker; on a
  file that did not reach that line in the recording shell, because it
  returned partway through or was sourced in a subshell; and on a file that
  left a shell option, the working directory, a trap or the umask other than
  it found them, naming each change.
- from: #204
- kind: defect-permitting
- status: active
- direction: static: it drives the routine against fixture files and reads
  what it printed and recorded
- note: Once the checks live in files the driver sources, every property one
  file run top to bottom had by construction is a claim about the sourcing,
  and each is a way to ask less and stay green: a file not sourced at all, one
  cut short, one whose rows went uncounted because it ran in a subshell, where
  `record` writes nothing, and one whose `req`, `set -f` or `cd` carried into
  the next. The end marker is written by the file's own last line and not by
  the routine after the `.`, because bash returns from `.` identically at the
  end of a file and at a `return` halfway through it (measured, bash 5.2); a
  marker written after the `.` would call a file that returned early whole.
  The state is written by the sourcing shell and not read through a `$( )`,
  where errexit reads as off whatever it is set to. What it does not see,
  named: a file whose middle was deleted, which still reaches its last line;
  a variable a file leaves set, which is how every file hands the next its
  fixtures and so is not a change; and a file descriptor it leaves redirected,
  which the `--matrix` program does on purpose.
