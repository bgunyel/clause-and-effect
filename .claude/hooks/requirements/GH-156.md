### GH-156
- text: `append-only-docs.sh` reads the command twice, as it came and with its
  backslash line continuations joined by `cs_join`, and refuses when either
  reading is refused. So every verb it names — `rm`, `mv`, `cp`, `truncate`,
  `tee`, `sed -i`, `perl -i` — and a truncating redirect are refused with a
  continuation anywhere between the verb and the path, or inside the path, as
  they are on one line; and a line bash does not continue — an even run of
  backslashes, or one in a comment — still leaves the command on the next line
  its own boundary. `>>` behind a continuation stays permitted, and so does a
  revisable directory. Its load guard requires `cs_join` beside
  `cs_tool_input` and `cs_within_cap`.
- from: #156, found by #106's invariance families on the first run of the
  `continuation` transformation against an `append-only-docs.sh` seed, which is a
  seed only because #141 brought the hook into their scope
- kind: defect-permitting
- status: active
- variants: transformation: continuation
- note: the hook matches paths where they stand, with `grep -E`, and `grep`
  matches within a line; the command never passed through `cs_join`, so a
  continuation between the verb and the path hid the path from a rule that
  requires both on one line. Measured: `rm`, `mv`, `cp`, `tee`, `truncate` and
  `>` were all permitted behind one backslash, and so was `sed` with a
  continuation before its `-i`. It was #84's shape again: `no-pr-decisions.sh`
  calls `cs_join` for this exact reason, one file away from the hook that did
  not. Its first version read the joined text alone, and that opened a hole
  of the same class the other way: `cs_join` joins any trailing backslash and
  bash continues only an odd run and never a comment, so `echo done \\`, a
  newline and `rm -f` an entry — refused before — was permitted, the verb glued
  onto the word before it (review of PR #329, round 1). The raw reading is what
  closes that, since it is the hook as it was. What the fix gives up is in the
  refusing direction only: `cs_join` joins every trailing backslash, including
  one a shell reads literally — inside single quotes, in a comment, in a quoted
  heredoc's body — so prose there ending a line in `rm \` and naming an entry on
  the next is refused; and `docs/dev-log\`, a newline and `book`, which is
  `docs/dev-logbook` to a shell, stays refused by the raw reading.
  `checks/GH-156.sh` pins every one of these. The same glued boundary in the
  hooks that read `cs_normalise`'s text is #337. Until #156 this entry was
  `gap → #156`, and the families' `docs-truncate + continuation` row asserted
  the permitting verdict; that variant is an ordinary check of the seed's BLOCK
  now.
