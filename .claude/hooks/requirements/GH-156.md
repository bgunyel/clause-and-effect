### GH-156
- text: `append-only-docs.sh` reads the command with its backslash line
  continuations joined, by `cs_join`, so every verb it names — `rm`, `mv`,
  `cp`, `truncate`, `tee`, `sed -i`, `perl -i` — and a truncating redirect are
  refused with a continuation anywhere between the verb and the path, or inside
  the path, as they are on one line. `>>` behind a continuation stays
  permitted, and so does a revisable directory. Its load guard requires
  `cs_join` beside `cs_tool_input` and `cs_within_cap`.
- from: #156, found by #106's invariance families on the first run of the
  `continuation` transformation against an `append-only-docs.sh` seed, which is a
  seed only because #141 brought the hook into their scope
- kind: defect-permitting
- status: active
- variants: transformation: continuation
- note: the hook matches paths where they stand, with `grep -E`, and `grep`
  matches within a line; the command never passed through `cs_join`, so a
  continuation between the verb and the path hid the path from a rule that
  requires both on one line. Measured: `rm`, `mv`, `cp`, `tee`, `truncate` and
  `>` were all permitted behind one backslash, and so was `sed` with a
  continuation before its `-i`. It was #84's shape again: `no-pr-decisions.sh`
  calls `cs_join` for this exact reason, one file away from the hook that did
  not. The fix gives up a case in the refusing direction: `cs_join` joins a
  trailing backslash inside quotes too, where a shell reads it literally, so
  quoted prose ending a line in `rm \` and naming an entry on the next is
  refused. It also moves one verdict the other way, rightly: `docs/dev-log\`,
  a newline and `book` is `docs/dev-logbook` to a shell, and is permitted.
  `checks/GH-156.sh` pins both. Until #156 this entry was `gap → #156`, and
  the families' `docs-truncate + continuation` row asserted the permitting
  verdict; that variant is an ordinary check of the seed's BLOCK now.
