### GH-204.8
- text: Every section heading the suite prints has at least one row recorded
  under it, a `---` subheading's rows counting for the `===` heading above it.
  `section` writes each heading down with the number of rows the ledger held
  when it was printed, and the end-of-run file fails on any heading the next
  one follows, or the ledger ends on, with no row between them.
- from: #204
- kind: defect-permitting
- status: active
- direction: static: it reads the headings the run wrote down against the
  ledger, and drives the reading with a fixture
- note: A move of checks from the unsplit file into an issue file carries rows
  away from the heading they printed under. A heading moved without its rows,
  or left behind when they moved, prints and asks nothing, and nothing said so.
  Rows printed only inside a subshell are not recorded and do not count, which
  is the #98 self-test's rule for what establishes something. What it does
  not see, named: a heading printed other than through `section` -- with an
  `echo`, say -- is not written down, and its rows count for the heading
  before it. Every `===` heading the suite printed went through `section` when
  this was written (review of PR #220, round 2), so the limit is one a future
  file could reach and none does; the driver's convention for a new issue
  file says its heading is printed with `section`.
