### GH-204.4
- text: The tooling beside the hooks is one rule, `TOOLING`: a regular
  expression over paths relative to `.claude/hooks/` that matches
  `check-hooks.sh`, `mutate-hooks.sh` and every file under `checks/`, at any
  depth, spelled identically in the suite and in the mutation harness. A path
  with an empty, `.` or `..` segment is not the tooling, and it is refused
  before the rule is asked: no text check names a file through one, and the
  harness refuses a registry row that does, as the suite's audit of the
  registry does. Every file the driver sources is the tooling. No file under
  `checks/` is on the suite's list of hook files or of tokeniser consumers, and
  the harness refuses a registry row that targets one.
- from: #204
- kind: defect-permitting
- status: active
- direction: static: it reads the rule, the lists it keeps out of, and what the
  harness's row check answers
- note: It was a list of two names, and a list is what the next file is not on.
  The next file here is an issue file, which every loop adds, so the rule is
  written for the directory and adding one never touches it. The directory is
  tooling for the reason the two names were. The suite runs from the repository
  whatever `CHECK_HOOKS_DIR` says, so a mutation to a copy of a file under
  `checks/` would be read and never executed. And the library names
  `lib/command-scan.sh` in code, so the tokeniser audit would count it as a
  consumer if it could see it.
  The rule was `checks/.+` until review of PR #216, which took
  `checks/../no-git-push.sh` as the tooling: a text check reading a hook
  through that spelling off `$SUITE_DIR` was accepted, and under an override
  it read this repository's hook and not the copy. The first fix, one level
  with no leading dot, reopened the class from the other side (round 2):
  `checks/./library.sh`, `checks//library.sh` and `checks/sub/x.sh` were not
  the tooling, so they were judged as hooks, and a hook read from `$HOOKS` or
  named in a registry row is accepted. So the rule is exact, and the
  spellings it does not take are refused where a path is written by hand
  rather than left to fall through.
