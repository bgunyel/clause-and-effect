# OpenRouter response bodies, 2026-09-05

**Observation, not result.** These are live OpenRouter request/response bodies
recorded on 2026-09-05, kept because four tickets on
[the LLM call log map](https://github.com/bgunyel/clause-and-effect/issues/6)
argue from what is *in* them. Nothing here is an analysis; the analyses live on
the tickets and cite back to these files.

They were rescued out of `tmp/` by
[#29](https://github.com/bgunyel/clause-and-effect/issues/29): an uncommitted
directory one `rm -rf` away from taking four tickets' evidence with it.

**No committed script produces these files.** The capture was ad hoc, during the
resolution of [#13](https://github.com/bgunyel/clause-and-effect/issues/13)
(*One live body, dumped whole*) and
[#14](https://github.com/bgunyel/clause-and-effect/issues/14). Nothing under
`scripts/` writes to this path - checked, not assumed. `scripts/probe_header_ab.py`
is a **different and later** instrument: it is #14's registered A/B, run at 15:14
local the same day, and it writes its own dated report. So these bodies **cannot
be regenerated by rerunning anything in this repository**, which is most of why
they are archived rather than left to be re-derived.

## What each file is

| file | what it holds |
|---|---|
| `all.json` | `{runs: [6], generation_window: {...}}` - the whole capture. Six paired calls, labelled `base-1`, `hdr-1`, `base-2`, `hdr-2`, `base-3`, `hdr-3`; each run is `{caller, wire[]}`, where `caller` is what LangChain handed back and `wire[]` is the request/response as it crossed `httpx`. |
| `base-N.json`, `hdr-N.json` | The six runs again, one per file, minus the `label` key. `base` sent no `X-OpenRouter-Metadata` header (`sent_header: false`); `hdr` sent `enabled`. All six returned 200 from `Baidu` with `finish_reason` and `native_finish_reason` both `tool_calls`. |
| `errors.json` | Three non-200-shaped probes, recording which headers survive a failure: `auth-fail+hdr` (401) carries **no** `x-generation-id`; `bad-model+hdr` (**400**) carries one; `ok-nostructured+hdr` (200) carries one. `x-provider-name` is null in all three. This is [#23](https://github.com/bgunyel/clause-and-effect/issues/23)'s evidence. |
| `generation_window.json` | **n=1.** One generation id polled against `/generation`: 404 at t=0.01, 2.33, 4.62 s, first 200 at **t=6.84 s**. Availability timing, one observation, no interval. |
| `pool.json` | **A summary, not a body.** Five request shapes against the same model, each recording `endpoints_total`, `available_n`, the selected provider and both finish reasons. `tools+require` and `tools+norp` see **23 of 30** endpoints; `notools+*` see **29 of 30** - the request-shaped pool that [#20](https://github.com/bgunyel/clause-and-effect/issues/20) argues from. Note the `finish_reason: tool_calls` / `native_finish_reason: length` split on the tool arms. |

`all.json` is a **verified strict superset**: each `base-N`/`hdr-N` file equals
the correspondingly labelled entry in `all.json["runs"]` once `label` is removed,
and `generation_window.json` equals `all.json["generation_window"]`. The
singletons are kept anyway - the whole directory is 117 KB, and deleting cited
evidence is the failure this directory exists to prevent.

## Redactions

`authorization` was already `<redacted>` at capture time - 12 occurrences, none
of them a live key.

Three further fields were redacted **by value, with the key preserved**, before
publishing, because `docs/eval-reports/` is public and these identify the
account rather than the observation. None is cited by any ticket.

| key | occurrences | what it was |
|---|---|---|
| `set-cookie` | 12 | Cloudflare `__cf_bm` bot-management cookies, one per response |
| `workspace_id` | 2 | the OpenRouter workspace UUID |
| `user_id` | 1 | the OpenRouter account id, inside the `/generation` record |

The keys are left in place so that *the field was present* stays readable - which
matters to [#18](https://github.com/bgunyel/clause-and-effect/issues/18), whose
`generation_record` JSONB archives that endpoint's body **whole**: the record
carries an account id, and any future dev-log or eval-report that pastes one
inherits this same redaction.

`app_id` (2524738), `cf-ray`, `http-referer` and `x-title` are **kept**. They are
LangChain's, not this account's, and they are the observation behind
[#25](https://github.com/bgunyel/clause-and-effect/issues/25) - that every
request already attributes this project's spend to LangChain's documentation site.

**The published files are not byte-identical to the capture.** They were
re-serialised (`json.dumps(indent=1)`) in the same pass that redacted them.
Checked, not assumed: parsed, the published data is identical to the verbatim
data once the three keys above are dropped from both. Both digests are recorded
so the transform stays auditable.

## Naming

[#27](https://github.com/bgunyel/clause-and-effect/issues/27)'s three-shape probe
writes bodies of the same kind, so it follows this directory's convention:
`docs/eval-reports/<date>-<what-was-observed>/`, a `README.md` carrying
provenance and per-file description, and redaction recorded rather than silent.
The directory is **append-only**, like the rest of `docs/eval-reports/`: a later
capture is a new directory, never an edit to this one.
